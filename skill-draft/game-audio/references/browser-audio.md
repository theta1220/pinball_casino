# ブラウザー音声の実装判断

- AudioContextは通常1つを共有し、ユーザーの明示操作に紐づけて開始・resumeする。Promise失敗やsuspended状態を扱い、自動再生できたと決めつけない。最初の操作が「ミュート解除」なら状態更新の順番に注意する。
- 短いSFXは事前読み込み・デコードしたバッファを再利用し、再生ごとに使い捨てsourceを作る。長いBGMは転送量・メモリ・ループ精度に応じてストリーミングかバッファを選ぶ。読み込み中でもゲームを固めず、失敗した素材だけを報告する。
- 音程と包絡は音声時計に予約する。requestAnimationFrameやsetTimeoutの精度でリズムを保証しない。予約には短い先読みと停止・再起動時のキャンセルを設ける。
- gain変更は現在の状態からランプする。exponential rampは0を終点にできないため、小さな正値まで下げて停止する。既存予約の取り消し時に不連続な段差を作らない。
- ループの継ぎ目は実際に数周聞く。MP3等の境界やデコード結果を検証せずgaplessと主張しない。必要ならループ点、クロスフェード、別形式を検討する。
- source終了時に接続と管理リストを解放する。pause/restart/タブ非表示で連続音が残らないことを確認する。音声再開はプラットフォームの制約を受けるため実機確認する。
- プリミティブなオシレーター合成は試作・様式として選び、録音素材と同等の質感だと扱わない。利用可能な生成ツールやライセンス済み素材を使う場合も、採用前に試聴する。

最低限の確認: 初回開始、ミュート前後、音量0、連打、同時衝突、pause/resume、restartの反復、タブ復帰、素材読み込み失敗。波形/ピーク測定は試聴の代わりではない。
