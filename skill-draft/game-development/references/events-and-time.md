# ゲームイベントと時計

小規模ゲームなら関数呼び出しでもよい。必要になったときだけ次の意味を持つイベントを導入する。

```js
// 一例。フィールド名を既存設計に合わせてよい。
{ id, type: 'impact', simTime, entityId, contactId,
  position: {x,y}, normal: {x,y}, impulse, material, seed }
```

音量・粒子数・揺れ強度は、同じimpactの正規化した強度からそれぞれ調整する。サブステップごとに同じ接触を再発火しない。音声のvoice制限や粒子の上限は表示側で行い、得点イベントを間引かない。コスメティックな乱数を物理用乱数と分離する。

impact、charge-start、charge-update、charge-release、reward、drain、pause、resume、restartなど、必要な意味だけ定義する。イベントにユーザー情報や秘密を混ぜない。履歴はローカルの再現に必要な範囲で保持する。

シミュレーション時刻はゲーム状態に、描画の補間率は見た目に、音声時刻は音の予約に使う。異なる時計の数値をそのまま比較しない。遅れた通知では古い効果を一括再生せず、その演出がまだ意味を持つか判断する。

一時停止時のポリシーを明示する。例: 物理と粒子を止め、BGMを短くフェードして停止し、UI操作音は維持する。復帰時は連続音の現在状態を復元し、過去の衝突音を再生しない。
